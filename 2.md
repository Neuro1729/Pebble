# Minimal working V2

V1 is **done** (see `1.md` + current `src/pebble`): sync disk, FIFO buffer pool, slotted pages, table heap, catalog, Volcano executors (Insert / SeqScan / Filter / Project / NestedLoopJoin), tiny SQL front end. Single-threaded, no indexes, no crash recovery.

**V2 goal:** real indexes + stronger buffer pool. Still single-threaded. Still no WAL / MVCC / 2PL.

Aligned with BusTub: finish P1-style buffer upgrades → P2-style B+Tree → wire IndexScan into planning (slice of P3).

## Data structures (new / upgraded in V2)

| DS | Role |
|----|------|
| Page guard (read/write RAII around a pinned frame) | Safer pin/unpin; required before B+Tree work |
| Disk request queue + worker (optional DiskScheduler) | Async-ish page I/O; BPM submits read/write jobs |
| ARC metadata (T1/T2 + ghost lists B1/B2) | Smarter victim selection than FIFO |
| B+Tree internal page (ordered keys + child `page_id`s) | Direct search down the tree |
| B+Tree leaf page (ordered keys + RIDs, sibling links) | Point lookup + ordered scan |
| Index metadata in catalog (`index_name → table, key schema, root page_id`) | Know which indexes exist |
| Index iterator (leaf walk via next-leaf pointers) | Range / ordered scans |

Skip for V2: undo/version chains, lock table, WAL, transaction table, hash index, cost-model stats, hash join spill pages.

## Algorithms

| Algorithm | Role | V1 today | V2 target |
|-----------|------|----------|-----------|
| Eviction | Free a frame | FIFO | **ARC** (or LRU-K as simpler alternate) |
| Disk I/O scheduling | Perform page R/W | Direct sync in BPM | **DiskScheduler** queue + background worker |
| Page access API | Borrow a page safely | Manual pin/unpin | **Page guards** (`with ReadGuard/WriteGuard`) |
| Point lookup | Find rows by key | Full SeqScan | **B+Tree search** → RID(s) → heap fetch |
| Index insert/delete | Maintain index with heap | None | **B+Tree insert** (split) / **delete** (merge or tombstone-first) |
| Range / ordered scan | Scan keys in order | None | **Leaf iterator** via sibling pointers |
| Index scan executor | Query operator | None | **IndexScanExecutor** |
| Planning rule | Prefer index | Always SeqScan | **Dumb rule:** equality on indexed col → IndexScan |

## Mental pipeline (V2)

```text
Disk file  ←→  [DiskScheduler]  ←→  Buffer pool (ARC + page guards)
                                            ↑
                         Table heap (slotted pages)   B+Tree index pages
                                   ↑                        ↑
                         Catalog: tables + indexes (root page_id, key cols)
                                            ↑
Plan: Insert (heap + index maintain)
      SeqScan | IndexScan → Filter → Project
      NestedLoopJoin (still ok)
                                            ↑
Executor Init/Next + tiny SQL / planner rules
```

That set is enough for V2. Swap FIFO → ARC and add IndexScan behind the same Volcano interfaces.

## Python build order

Build on top of V1. Prefer swapping implementations behind existing interfaces (e.g. replace `FifoReplacer` with `ArcReplacer`). Each step should work (and be testable) before the next.

### 1. Page guards
- `ReadPageGuard` / `WritePageGuard`: pin on enter, unpin on exit (`contextlib` / `with`)
- Refactor heap / slotted usage to use guards (stop leaking pins)

**Done when:** insert + scan still pass; pin_count returns to 0 after operations.

### 2. ARC replacer (replace FIFO)
- Implement ARC lists / ghost entries
- `BufferPoolManager` uses `self._replacer = ArcReplacer(...)` (same swap point as V1 `FifoReplacer`)

**Done when:** eviction tests still pass; simple thrash smoke test is no worse than FIFO.

### 3. DiskScheduler (optional but BusTub-aligned)
- Queue of read/write requests
- Background thread calls `DiskManager`
- BPM waits for completion (Future/Event)

**Done when:** BPM fetch/flush works only through the scheduler; existing heap tests pass.

### 4. B+Tree pages
- Layout for internal + leaf pages inside `PAGE_SIZE` (via BPM)
- Header: page type, size, parent / next sibling as needed
- Binary search within node

**Done when:** manually build a small tree of pages; search finds keys; dump helpers help debug.

### 5. B+Tree operations
- `search(key) -> list[RID]` (or single RID for unique)
- `insert(key, rid)` with **split**
- `delete(key, rid)` with merge or tombstone-first naive delete
- Keep tree balanced

**Done when:** insert many keys, search hits, delete removes; survive flush + reopen from root `page_id`.

### 6. Index iterator
- Start at leaf for `key` / lowest key
- `next()` walks leaf slots then sibling leaf pages

**Done when:** in-order traversal matches sorted keys.

### 7. Catalog: indexes
- `create_index(name, table, key_columns)`
- Store `{name, table, key schema, root_page_id, is_unique?}`
- On heap insert (and delete if you have it), update secondary indexes

**Done when:** create table + index; insert rows; index search returns correct RIDs; heap get returns tuples.

### 8. IndexScanExecutor
- Use index to get RIDs (point or range), then fetch tuples from heap
- Optional: push simple key predicates into the scan

**Done when:** `IndexScan` result matches `SeqScan + Filter` on the same predicate.

### 9. Planner rule + SQL
- `CREATE INDEX ...`
- `SELECT ... WHERE indexed_col = ?` → plan IndexScan (dumb rule, no cost model)
- Keep NLJ; no hash join yet

**Done when:** end-to-end SQL demo uses an index for an equality lookup.

### What not to start with in V2
Optimistic latch crabbing / multi-threaded B+Tree, hash join, external sort, window functions, MVCC undo chains, 2PL, WAL/ARIES, cost-based optimizer.

# Minimal working V1

For a minimal working V1 (create table, insert, select with filter, optional nested-loop join), single-threaded, no crash recovery:

## Data structures

| DS | Role |
|----|------|
| Fixed-size page (byte array, e.g. 4KB/8KB) | Unit of disk I/O and caching |
| Slotted page (header + slot directory + tuple bytes) | Store variable-length rows in a page |
| Table heap (linked list / chain of page IDs) | One table = many pages |
| RID `(page_id, slot)` | Point at one tuple |
| Buffer pool (array of frames + `page_id → frame` map) | Cache pages in memory |
| Pin count + dirty bit per frame | Know what is in use / must be written back |
| Schema (column name + type list) | Interpret tuple bytes |
| Tuple (serialized row bytes) | Row value |
| Catalog (`table_name → {schema, first_page_id}`) | Metadata |
| Plan tree (tiny: SeqScan / Filter / Project / Insert / NLJ nodes) | What to run |
| Volcano iterators (`Init` / `Next`) | Pull tuples through operators |

Skip for V1: B+Tree, hash tables for indexes, undo/version chains, lock tables, WAL.

## Algorithms

| Algorithm | Role | Naive choice |
|-----------|------|--------------|
| Page read/write | Persist pages | Sync file seek + read/write at `page_id * PAGE_SIZE` |
| Buffer fetch | Get page into a frame | Lookup map; on miss, pick victim, write if dirty, read from disk |
| Eviction | Free a frame | FIFO or CLOCK (not ARC yet) |
| Slotted insert / get | Put/get tuple in a page | Find free space, add slot, copy bytes |
| Heap insert | Insert into table | Try last page; else allocate new page, link it |
| Sequential scan | Read all rows | Walk page chain, walk slots |
| Selection (filter) | WHERE | Per-tuple predicate check |
| Projection | Pick columns | Copy chosen fields into a new tuple |
| Nested-loop join | Join two inputs | For each left tuple, scan right (or nested `Next`) |
| Insert executor | INSERT | Build tuple → heap insert |
| Dumb planning | SQL/AST → plan | Hardcode one shape (no optimizer) |

Skip for V1: ARC/LRU-K, async disk schedule, B+Tree search/split/merge, hash join, external sort, 2PL/MVCC, WAL/ARIES, cost-based optimize.

## Mental pipeline

```text
Disk file  ←→  Buffer pool  ←→  Table heap (slotted pages)
                                      ↑
Catalog (name → schema + heap)
                                      ↑
Plan: Insert / SeqScan → Filter → Project
              └─ NestedLoopJoin (optional)
                                      ↑
Executor Init/Next loop
```

That set is enough for V1. Everything else is a later swap (same interfaces, better algorithm inside).

## Python build order

Build bottom-up in Python. Each step should work (and be testable) before the next.

### 1. Types + Schema + Tuple
- Column types (`int`, `str` is enough)
- `Schema`: list of `(name, type)`
- `Tuple`: encode/decode values ↔ bytes using the schema

**Done when:** you can serialize a row and read it back in memory (no disk yet).

### 2. Page + DiskManager
- Fixed `PAGE_SIZE` bytearray
- `DiskManager`: open a file, `read_page(page_id)`, `write_page(page_id)`, `allocate_page()`

**Done when:** write random bytes to page 0, reopen file, read them back.

### 3. Buffer pool (naive)
- Frame array, `page_id → frame` map
- pin / unpin, dirty bit
- `fetch_page`, `new_page`, `unpin_page`, `flush`
- Eviction: **FIFO** (simplest)

**Done when:** fetch more pages than pool size; old pages evict; dirty ones hit disk; data still correct.

### 4. Slotted page
- Layout: header, slots, tuple bytes
- `insert_tuple`, `get_tuple`, iterate valid slots
- Works on a raw page buffer (from the buffer pool)

**Done when:** insert several tuples into one page, read them by slot, survive flush + reload.

### 5. Table heap
- Chain of page ids (`next_page` in header, or store `first`/`last` in catalog)
- `insert` (use last page, else allocate + link)
- `scan` (walk pages + slots → yield `(RID, tuple)`)

**Done when:** insert 100+ rows across multiple pages; scan returns all of them after reopen.

### 6. Catalog
- In-memory: `name → {schema, first_page_id, …}`
- `create_table`, `get_table`
- (Optional V1: also persist a simple catalog page; in-memory is fine at first)

**Done when:** create two tables, insert into each, get the right heap back by name.

### 7. Executors (Volcano): Insert + SeqScan
- Base: `init()` / `next()` → tuple or `None`
- `InsertExecutor`
- `SeqScanExecutor`

**Done when:** programmatic “insert N rows, seqscan all” works through executors (still no SQL).

### 8. Filter + Project
- `FilterExecutor` (predicate on tuple)
- `ProjectExecutor` (keep some columns)

**Done when:** scan → filter → project matches a hand-checked result.

### 9. Nested-loop join (optional but in V1 list)
- `NestedLoopJoinExecutor`: for each left, rescan/reset right, emit matches

**Done when:** join two small tables on `a.id == b.a_id`.

### 10. Dumb planner + tiny front end
- Either:
  - tiny SQL (`CREATE TABLE`, `INSERT`, `SELECT … WHERE`), or
  - a Python API that builds the plan tree
- Planner: hardcoded shapes only (no optimizer)

**Done when:** end-to-end demo: `create → insert → select with where` (and join if you did step 9).

### What not to start with
Indexes, ARC, async I/O, transactions, WAL, real SQL parser, optimizer.

### Suggested milestones

| Milestone | Steps | You can say |
|-----------|-------|-------------|
| M1 | 1–3 | “Pages cache correctly” |
| M2 | 4–6 | “Tables store rows on disk” |
| M3 | 7–8 | “Filtered select works” |
| M4 | 9–10 | “V1 complete” |

**Start at step 1** (Schema/Tuple). Everything else hangs off correct row bytes.
